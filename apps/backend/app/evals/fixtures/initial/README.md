# Initial shopping corpus

This directory contains 24 **synthetic** shopping scenarios. No content was
fetched, recorded from a real shopper, or generated by a live model. Product
names, prices, offers, excerpts, ratings and availability are invented inputs.
YouTube, Reddit, Amazon and IKEA URLs illustrate the required source identities
and country paths; they are not verified pages and must not be fetched when
loading or checking this corpus. Links are neutral and contain no credentials
or affiliate parameters.

- `inputs.json` holds versioned fixture inputs keyed by case name: shopping
  requests, supplied briefs for later-stage work, products/listings, short source
  excerpts with evidence IDs/targets, uncertainty notes, and refinement context.
- `cases.json` independently declares case descriptions, coverage tags, expected
  fields and criteria with source/evidence IDs where factual grounding matters.
  Expectations are specifications, not canned production output schemas.
- `app.evals.initial_dataset.initial_cases()` resolves the fixtures and validates
  references. `initial_dataset()` exposes them as Pydantic Evals cases. Loading
  performs no agent execution, settings loading, database writes or network work.

Requests, briefs, products, listings, manual candidates, money, region and
evidence targets use production schemas. `ShoppingSourceFixture` is a compact
eval-only source document, **not** a recorded provider cassette, production
`SourceSnapshot`, or already verified source-intelligence bundle. Later task
adapters must explicitly convert the relevant input to production contracts;
they must not pass expectation criteria to the agent or return them as results.

All IDs and observation times are fixed. Intake/guardrail scenarios need no
product sources; their fixtures are the request and optional answers. Other
scenarios include source excerpts or explicit gaps. Positive and negative source
conditions are combined within the four source scenarios to keep the corpus at
24 cases. This is a compact baseline, not exhaustive failure/provider coverage.

Keep expectations independent from fixture-derived actual results. Add cases,
inputs, and the case table in `docs/EVALUATION.md` together. Corpus-integrity
tests live in `tests/test_initial_eval_dataset.py`; they do not run scored evals.
The separate `../intake_planning.json` corpus expands the intake and regional
planning specifications with executable mocked-contract adapters and named
assertions; it reuses the US grinder brief. The initial 24-case corpus itself
remains an acceptance specification. The separate `../discovery_extraction.json` corpus adds source selection/quality,
extraction fidelity and conservative dedupe assertions with deterministic services
and explicit mocks. The separate `../trust_recommendation.json` corpus adds
shopping guardrails, seller-risk, independent picks, budget/citation/conflict
criteria and safe output verification to the regular quality gate, using production
contracts with explicit mocks. The separate `../source_intelligence.json`
corpus adds YouTube, Reddit, Amazon and IKEA service/specialist-contract checks
with synthetic providers and explicit mocks, plus scoped downstream evidence
probes through an eval-only bridge. It does not change owner/workflow behavior.
The CLI defaults to scaffolding and offers
`--suite intake-planning`, `--suite discovery-extraction` and
`--suite trust-recommendation` and `--suite source-intelligence`; it does not run the
full initial corpus. `--suite quick` selects 27 fixed cases from the executable
lanes, retaining regression coverage and existing independent expectations.
`--suite full` runs quick first and then all 108 executable cases.
The 24 cases in this directory remain specification-only and are covered by
the Section Q integrity tests. See `docs/EVALUATION.md` for the selection,
report manifests and combined offline gate.
